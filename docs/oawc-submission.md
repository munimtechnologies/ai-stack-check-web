# Open Agentic Web Challenge: submission draft (AI Stack Check)

Status: draft. The agentic version is on the `agentic-web` branch until its build and browser tests pass. Entrant: Munim, Inc. (organization), with an adult Representative as the rules require. Made by MV2 of Munim, Inc. with AI agents.

## Project name
AI Stack Check: an agentic website that fixes self-hosted AI stacks without seeing your secrets

## Elevator pitch (200 characters)
Paste your Ollama/Open WebUI/vLLM compose file. Fixed rules find exposed APIs and known advisories in your browser; an in-browser agent on your own model explains them and proves its fix passes.

## The problem
Teams now run their own AI stacks: Ollama, Open WebUI, vLLM, LiteLLM, n8n, Dify. Two kinds of mistake recur. An API with no login of its own gets published on every network interface (Ollama, ComfyUI, vLLM without `--api-key`). And versions with known advisories stay pinned, including advisories that have no CVE yet and that ordinary scanners miss. The people who can fix this are not security specialists, and the file that describes the stack is full of secrets, so pasting it into a chatbot is the wrong answer.

## What it does
- **Deterministic checks first.** The browser runs fixed exposure rules and a curated advisory list ([ai-stack-advisories](https://github.com/munimtechnologies/ai-stack-advisories), 210 advisories, Apache-2.0) on the pasted file. Nothing is uploaded.
- **An agent network that uses the site, not a copy of it.** The open agentic web runtime runs in the browser. Its front agent, `stack_check_assistant`, gets six `website_*` tools that wrap the page's own functions (`App.page`): `get_findings`, `check_pasted_file`, `load_sample_stack`, `get_redacted_file`, `check_component` and `verify_fix`.
- **Private context by construction.** No tool returns the raw file. The agent sees findings, or a redacted copy in which secrets, credentials in URLs, private keys and public IPs are replaced.
- **Bring your own model, including your own machine.** Any OpenAI-compatible provider works. So does the visitor's local Ollama (`http://localhost:11434/v1` with `OLLAMA_ORIGINS` set). Then the whole loop (page, agent and model) runs on the visitor's computer.
- **The agent proves its fix.** Before it shows a corrected compose file, it must call `verify_fix`. That runs the same rules on its draft and reports any high-severity problem left and any value that looks like a secret.
- **Grounded answers.** The instructions forbid advisory IDs that no tool returned, and the page's existing invented-ID guard flags any that slip through.

## How it uses the open agentic web spec
- `agent-manifest.json` at the site base; `ai_stack_check.network.json`, built from `ai_stack_check.hocon` with the reference `build_network.mjs` (validated with `--check`); `links.json`; `agent-mcp.json` and `.well-known/` generated by the build.
- The runtime (`runtime/`) and bridge come from cognizant-ai-labs/agentic-web (Apache-2.0), unmodified.
- `peer_rules`: when another site's assistant calls this network, it can only describe the service and never invents findings.
- Static hosting (GitHub Pages), with a CSP that allows only the visitor's chosen model endpoint for `connect-src`.

## What was built during the Submission Period
The page (v0.1, a plain in-browser checker) existed before. After 2026-11-11 we added the whole agentic layer: the page-object refactor so buttons and tools share one implementation, the six tools, the network and manifest, the assistant UI, the `verify_fix` loop, and the tests (`test/agentic.test.mjs`, `scripts/agentic-smoke.mjs`).

## Built with
JavaScript (no framework), the open agentic web runtime, Neuro SAN network format (HOCON), GitHub Pages, Node test runner, Playwright.

## Testing instructions
1. Open https://munimv2.github.io/stack-check/ in a current desktop browser.
2. Press "Try a sample stack" (no model needed): 5 exposure problems and outdated components appear.
3. In "Ask AI Stack Check", open "AI model settings" and enter any OpenAI-compatible endpoint and key (a key with a low spending limit is best), or point it at a local Ollama.
4. Ask: "What do I fix first?", then "Write me a corrected compose file and check that it passes."
